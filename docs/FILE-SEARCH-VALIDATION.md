# 内置文件搜索验证摘要

更新于 2026-10-23。这里保留当前实现的验收结果，使用方法见 [文件搜索](FILE-SEARCH.md)，权限与恢复决策见 [ADR 0003](adr/0003-builtin-file-search.md)。历史原型报告和原始采样仅在本机归档，不随源码提交或打包。

## 已验证的日常流程

集成功能验证使用隔离的 Kite profile、真实 C/D/E 三卷和专用验证目录：

- 三卷的新增、删除、重命名能同步到搜索；重启复用同一基库，补齐退出期间的变化后继续实时同步。
- 排除目录按当前路径隐藏自身与子树；实测结果由 3 条降至 2 条，重启保留设置，移除排除后恢复 3 条。内核对照覆盖了类型筛选、大小写和硬链接的逐路径排除。
- 实际重建完成后切换到新的完整基库；旧基库清理，恢复所需的受保护起始游标保留。服务退出与重建连接交错的问题已修复并实测。
- 窗口隐藏期间继续跟踪变化，暂停无用 UI 查询；恢复后能搜索到期间新增的文件，随后删除也能同步。
- 关闭插件约 1 秒内，读取服务停止；客户端进程结束也会停止读取。首次安装、组件更新和按需启动已实际执行。

## 最新 Release：约 3.25 秒文件就绪，约 90 MiB 合计工作集

复用同一份 **3,255,185 条路径的 C/D/E 基库**，交替运行目录匹配优化前后各 3 次。使用独立 Release 测量构建，UI 与读取组件均为 Release；未重建索引、未清空系统缓存，也未覆盖正在使用的安装版。每次从读取服务停止状态开始，后台补读累计的真实 USN 变化。

| 指标 | 优化前 | 优化后 |
|---|---:|---:|
| 进程启动至文件搜索 Ready，中位数 | 5.064 秒 | 3.254 秒 |
| 上述 3 次样本范围 | 4.932–5.390 秒 | 2.983–3.309 秒 |
| Kite 窗口创建事件，中位数 | 269 ms | 294 ms |
| 热查询：输入开始至 UI 收到结果，中位数 | 187 ms | 188 ms |

主界面启动不等待文件索引。窗口创建与 Ready 分别计时；首帧和首次可交互时刻未单独测量，查询终点也未包含像素绘制完成。实时 USN 输入随时间变化，固定输入的算法比较见下一节。

两版各完成相同 22 个关键词的 132 次真实输入查询，再隐藏窗口、等待 3 秒、采样 7 次。优化后各进程的中位数如下，单位为 MiB（1 MiB = 1,048,576 字节）：

| 进程 | 工作集 | 专用驻留 | 专用提交 |
|---|---:|---:|---:|
| Kite（含界面与应用索引） | 76.24 | 33.14 | 38.92 |
| 元数据读取组件 | 13.71 | 4.41 | 6.58 |
| **合计** | **89.95** | **37.55** | **45.50** |

工作集合计可能重复计算共享页，系统文件缓存与内核分配未计入。此次优化的明确收益是准备更快，常驻维持低内存水平；两版间的小幅内存差异不作为确定节省量。

## 同一份真实日志：状态与查询结果一致

使用上述基库和同一份 **8,433 项真实变化**，以旧版先运行、新版先运行两种顺序离线回放。优化前后完整 shadow 位图、818 个 shadow ordinal、1,469 个对象的身份与原始 UTF-16 路径、目录映射和状态逐项一致；22 个关键词的总数、前 20 条路径顺序、UTF-16 与目录标记均一致。状态无 stale 或 rebuild_required。

两次离线打开的中位数由 **2.104 秒降至 0.555 秒，耗时减少 73.6%**。目录匹配使用扫描组内的临时前缀结构，组结束即释放；未增加常驻全库缓存或持久恢复点。每次重启仍从不可变基库的原始游标补读。
