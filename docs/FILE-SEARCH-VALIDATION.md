# 内置文件搜索验证摘要

更新于 2026-10-23。这里区分当前改动的验证边界与历史版本验收结果，使用方法见 [文件搜索](FILE-SEARCH.md)，权限与恢复决策见 [ADR 0003](adr/0003-builtin-file-search.md)。历史原型报告和原始采样仅在本机归档，不随源码提交或打包。

## 当前改动：磁盘变化层与持久恢复（方案 B）

本轮处理正常大批文件变化仍可能挤满 65,536 个存活对象的问题。待处理身份和查询变化层改存 SQLite；变化对象与目录前缀按身份更新、删除，内存只保留有限缓存。65,536 对象／64 MiB 变化层及单会话 512 MiB 日志的累计容量失败条件被移除。

实现约定：

- watcher 临时 pending 数据库使用 4 MiB 缓存，按页读 USN；输出帧控制在 128 项／约 1 MiB，完整逻辑轮次才作为一笔事务发布。
- generation 下的 `live-state.sqlite` 保存可直接查询的变化对象、目录前缀及恢复状态。全卷 cursors 与 overlay、shadow、prefix 更新在同一事务提交，重启只续读完整提交位置之后的变化。
- 查询通过独立只读连接，在同一读事务内读取 shadow、提交序号、目录映射和变化对象。后台提交大轮次时，查询继续读取最后完整提交的视图；状态读取也不等待写入锁。
- 原基库保持不可变，原始受保护 checkpoint 继续作为卷与 journal 身份锚点。已删除记录通过数据库空闲页复用及 WAL checkpoint 控制增量写入；本轮暂不全量重写基库。
- feed 每约 32 MiB 切段，消费端在数据持久消费后按帧 ACK，服务回收同一 session 内已完整消费的旧段。服务协议升级为 3，旧读取组件需要用户授权更新。
- 磁盘满、写入失败、真实 journal 身份或连续性丢失仍明确报错，保留最后完整提交状态。未提交轮次重启后重读。

本轮已通过默认 `cargo check --locked --offline`、修改文件的定向 rustfmt 检查及 `git diff --check`。复用已有 Debug 查询工具，在隔离副本上回放 **3,255,185 条路径基库与 8,433 项真实录制变化**；原有 22 个关键词（全部类型、无排除目录）的完整查询与限量查询全部一致，与原报告的路径、原始 UTF-16、目录标记和总数也全部一致。回放后为 1,469 个变化对象、818 个 shadow ordinal，无 stale 或 rebuild_required；`journal_stopped=true` 是完整录制日志结束后的正常状态。回放材料与对照保存在本机 `.data/durable-journal-v1/`。本轮没有新增测试用例，没有安装、替换或重启现用组件，也没有在本机正式打包。

回放曾暴露普通目录删除逐一扫描基库的性能回退，已恢复最多 128 项／约 1 MiB 的有界删除合批，并在目录映射改变前与 fresh paths 提交前刷新。最终回放使用修正后的代码。此次 Debug 回放用于行为核对，不与下面历史 Release 性能数字比较；下面的 308 组查询对照、607 项既有检查及实机性能均来自各自历史阶段。

同一份 8,433 项真实日志已转换成新逻辑轮次格式，以每帧最多 128 项分块并按身份标记消失对象。通过同一既有工具回放后，22 组完整／限量查询、原报告结果及总数一致，变化对象与 shadow 数量也一致，无 stale 或 rebuild_required。新轮次回放与对照记录在 `.data/durable-journal-v1/rounds-audit.json` 和 `rounds-comparison.json`。

正式打包、安装验收与上传由 GitHub Actions 执行。独立 runner 使用已安装程序的诊断入口驱动生产控制器：停机期间创建 70,002 个真实存活文件，要求变化层对象数超过 65,536；核对哨兵查询、同基库重启后从持久游标续读，以及实际日志切段和旧首段回收，再验收覆盖安装及卸载。结果绑定安装器与主程序哈希并随 `installer-validation.json` 发布，任何一项失败阻止发布。具体提交的通过情况以该次 Actions 报告为准。

强制进程中断、磁盘满／写入失败恢复、人工 UAC 拒绝及长期在线观察仍为单独验收边界，不能由上述检查推断通过。

## 历史阶段：增量补读的身份回收

修正历史变化涉及超过 65,536 个不同对象时直接报 `journal pending-object limit` 的处理方式：每轮冻结全卷终点、分页读取；达到压力点时先用 MFT ordinal/sequence 验证原身份已经消失，按身份提交删除并回收。所有存活对象继续跨页合并、统一刷新和提交，避免跨批旧目录事件破坏较新的路径。回收和长刷新期间输出心跳，发布追平标记前重新检查日志连续性。存活变化层的 65,536 对象／64 MiB 及单会话 512 MiB 日志保护保留。

本轮未新增测试用例。应用 `cargo check --locked --offline`、修改文件格式与 diff 检查通过；复用既有库检查，607 项通过、10 项忽略。独立审核指出并修正了跨批目录命名空间、长刷新后日志连续性及 Windows MFT 输出缓冲区对齐问题。

复用已有 Release 查询工具，读取保留的 3,255,185 条路径基库及同一份 8,433 项真实变化日志，308 组查询的完整接口与限量接口全部一致。与此前报告逐组比较，总数和包含原始 UTF-16、目录标记的结果集合均一致；307 组顺序一致，另一组仅两条变化层结果互换位置，查询代码原有 `HashMap::values()` 遍历未规定跨进程顺序。本轮未修改排序逻辑。回放状态无 stale 或 rebuild_required；原始报告与比对结果保存在 `.data/journal-catchup-v1/`。

以上离线回放验证旧 feed 兼容和搜索结果，未执行候选 watcher 的真实 USN 读取。当前没有可复用的独立 watcher CLI；隔离 GUI 仍连接现用服务，不能用于证明候选内核生效。因此超过上限的真实 USN 压力回收、实时心跳、协议 1／2 混合升级和 UAC 更新尚待候选读取组件的实机验收。本轮未安装或替换读取组件，未重启现用 Kite。

## 历史版本已验证的日常流程

集成功能验证使用隔离的 Kite profile、真实 C/D/E 三卷和专用验证目录：

- 三卷的新增、删除、重命名能同步到搜索；重启复用同一基库，补齐退出期间的变化后继续实时同步。
- 排除目录按当前路径隐藏自身与子树；实测结果由 3 条降至 2 条，重启保留设置，移除排除后恢复 3 条。内核对照覆盖了类型筛选、大小写和硬链接的逐路径排除。
- 实际重建完成后切换到新的完整基库；旧基库清理，恢复所需的受保护起始游标保留。服务退出与重建连接交错的问题已修复并实测。
- 窗口隐藏期间继续跟踪变化，暂停无用 UI 查询；恢复后能搜索到期间新增的文件，随后删除也能同步。
- 关闭插件约 1 秒内，读取服务停止；客户端进程结束也会停止读取。首次安装、组件更新和按需启动已实际执行。

## v0.6.2 交互查询优化：结果顺序不变，输入响应约减半

在 v0.6.1 基础上取消已过期的在途查询，界面取够原有前 20 条后提前停止基础表扫描，不再计算界面未使用的完整命中总数。类型筛选、排除目录、基础结果优先于变化层、路径去重及原始 UTF-16 处理共用原有逻辑；原有完整查询接口仍返回精确总数。没有增加输入等待、全库常驻缓存、依赖或索引格式。

固定输入验证使用原 **3,255,185 条路径**基库及 **8,433 项真实变化**。原 22 个关键词、七种类型、两组排除配置共 308 组对照中，完整查询与限量查询的路径、顺序、原始 UTF-16 字段及目录标记全部一致；优化前后独立内核运行的 66 项结果对照也无差异。

实际窗口测量使用独立 Release 构建（仅开启隔离 profile 特性）与同一份新建的 **3,242,698 条路径 C/D/E 索引**。两版各输入 22 词、首轮加五轮热查询共 132 次，再执行相同的 12 次逐字输入。旧测量库的 D 盘 USN 起点已过保留范围，因此只在测量目录建了一份新库，优化前后共用；未修改安装版或用户现用索引。

旧版有 14 次回调为“查询已更新”状态行：后台线程入队顺序可能与输入顺序不同，原有队列合并会丢弃真正的新请求。新版在 UI 线程同步创建取消令牌，队列忽略已取消请求，本轮未出现此类异常。下表仅比较两版都正常返回结果的配对样本；首轮 19 对、热查询 99 对，逐字输入 12 对全部正常。

| 输入至 UI 收到结果 | 优化前 | 优化后 |
|---|---:|---:|
| 首轮，中位数 | 211 ms | 105 ms |
| 热查询，中位数 | 201 ms | 106 ms |
| 热查询，P95 | 259.4 ms | 135.1 ms |
| 逐字输入，末字符至结果中位数 | 199 ms | 94.5 ms |

计时终点为 UI 收到当前查询的结果日志，未计像素绘制完成；P95 使用线性插值。窗口测量期间 USN 持续更新，固定状态的结果一致性以前面的同日志对照为准。独立内核交替运行旧／新／新／旧，各版合计 132 次查询，中位数为 97.10／88.63 ms；窗口收益更大，主要来自减少过期输入阻塞。

相同搜索序列完成后隐藏窗口、等待 3 秒、采样 7 次，单位 MiB：

| 进程与版本 | 工作集 | 专用驻留 | 专用提交 |
|---|---:|---:|---:|
| 优化前 Kite | 90.22 | 37.37 | 44.61 |
| 优化前读取组件 | 14.36 | 4.84 | 6.29 |
| **优化前合计** | **104.58** | **42.21** | **50.90** |
| 优化后 Kite | 75.98 | 34.12 | 39.14 |
| 优化后读取组件 | 14.56 | 5.28 | 7.05 |
| **优化后合计** | **90.54** | **39.40** | **46.20** |

本轮常驻采样没有增加；小幅内存差异受线程、分配器和系统状态影响，不作为固定节省量。合计工作集可能重复计算共享页，系统缓存与内核分配未计入。独立窗口的文件模式与结果布局已实际查看，正常结果未改序；关闭测量进程后读取服务已停止。

上述性能测量阶段的默认 `cargo check --locked --offline`、既有库测试（607 通过、10 忽略）、隔离 Release 构建及 diff 检查通过；未新增测试用例。测量未覆盖正在运行的 Kite，未更新服务组件或安装包。本机详细报告、原始采样和独立预览保存在 `.data/query-opt-v1/`，不随源码提交或打包。本轮未重复长时间在线观察，正式构建与安装包信息见 [v0.6.2 发布说明](releases/v0.6.2.md)。

## 目录匹配优化的既有 Release 记录

复用同一份 **3,255,185 条路径的 C/D/E 基库**，交替运行目录匹配优化前后各 3 次。使用独立 Release 测量构建，UI 与读取组件均为 Release；未重建索引、未清空系统缓存，也未覆盖正在使用的安装版。每次从读取服务停止状态开始，后台补读累计的真实 USN 变化。

| 指标 | 优化前 | 优化后 |
|---|---:|---:|
| 进程启动至文件搜索 Ready，中位数 | 5.064 秒 | 3.254 秒 |
| 上述 3 次样本范围 | 4.932–5.390 秒 | 2.983–3.309 秒 |

主界面启动不等待文件索引。窗口创建与 Ready 分别计时；首帧和首次可交互时刻未单独测量，查询终点也未包含像素绘制完成。实时 USN 输入随时间变化，固定输入的算法比较见下一节。

两版各完成相同 22 个关键词的 132 次真实输入查询，再隐藏窗口、等待 3 秒、采样 7 次。优化后各进程的中位数如下，单位为 MiB（1 MiB = 1,048,576 字节）：

| 进程 | 工作集 | 专用驻留 | 专用提交 |
|---|---:|---:|---:|
| Kite（含界面与应用索引） | 76.24 | 33.14 | 38.92 |
| 元数据读取组件 | 13.71 | 4.41 | 6.58 |

工作集合计可能重复计算共享页，系统文件缓存与内核分配未计入。此次优化的明确收益是准备更快，常驻维持低内存水平；两版间的小幅内存差异不作为确定节省量。

## 同一份真实日志：状态与查询结果一致

使用上述基库和同一份 **8,433 项真实变化**，以旧版先运行、新版先运行两种顺序离线回放。优化前后完整 shadow 位图、818 个 shadow ordinal、1,469 个对象的身份与原始 UTF-16 路径、目录映射和状态逐项一致；22 个关键词的总数、前 20 条路径顺序、UTF-16 与目录标记均一致。状态无 stale 或 rebuild_required。

两次离线打开的中位数由 **2.104 秒降至 0.555 秒，耗时减少 73.6%**。目录匹配使用扫描组内的临时前缀结构，组结束即释放；未增加常驻全库缓存或持久恢复点。每次重启仍从不可变基库的原始游标补读。
