# Loci 原型基准：Windows 合成记录与有限文件系统验证

测量日期：2026-10-02。主工程：**`D:\Project\Loci`**。配套 [Linux 方案](linux-loci-plan.md)、[官方来源核实](linux-file-search-sources.md)。这是索引记录与查询开销实验，**没有 Linux 实测，没有创建一百万个真实文件，没有接入 Kite**。

## 实测结论

百万条重复结构的合成记录：磁盘索引 **46.39 MiB**（48,639,956 bytes），构建 p50 **916.72 ms**，查询后工作集 **55.16 MiB**、private commit **48.76 MiB**；建库峰值工作集 **66.99 MiB**、峰值 private commit **73.92 MiB**。短词 `q` 无命中首批热查 p95 **342.17 ms**，多词 `doc report` 无命中首批热查 p95 **384.02 ms**。

稀少匹配 `invoice_00001234` 热查首批 p95 **0.1028 ms**，中文、大量匹配、扩展名等首批常见案例也很快，但它们只取记录顺序的前50条。结果**不证明完整排序后的 UI 首屏速度**，也不证明所有查询达到100ms探索目标。低内存路线值得继续，但短词、扩展名与块内不同文件的多词假阳性必须先补强。

MiB = 1,048,576 bytes；所有下文延迟为 **ms**。此前提到的100MB常驻／100ms首屏是探索目标，没有被改成产品承诺。

## 方法与环境

- Windows 11 教育版 10.0.26200，Intel i5-13490F（10物理核／16逻辑处理器），RAM 34,115,448,832 bytes（约31.77 GiB）；D盘NTFS。系统枚举SSD为 SOLIDIGM SSDPFKKW512H7、HYV1TBX4(Pro)，没有进一步核实D分区与具体物理盘的对应，故不把某个SSD型号标作本次I/O设备。
- `rustc 1.99.0 (b940084d7 2026-09-28)`，host x86_64-pc-windows-msvc，LLVM23.1.1；cargo1.99.0；PowerShell7.6.6、Python3.12.10。release opt-level3、codegen-units1、LTO；不设置target-cpu=native，不引入第三方Rust依赖或GUI。
- 语料生成在Rust迭代器内，固定编号和格式；百万条父路径形如 `/home/test/项目/workspace_000/src/module_000`，4096个父目录，每10条轮换report/pdf、报告/docx、image/png、source/rs、invoice/txt、ab_notes/md、backup/zip、日志/log、video/mp4、readme/md；唯一8位编号。十万条1563个父目录。父路径高度重复，词汇少，仅1368种byte trigrams，**不是随机磁盘树或真实用户分布**。
- 名称原始UTF-8 byte pool＋父路径共享＋12-byte Record（parent／offset／len）；每64条记录块汇总规范化完整路径的三字节trigram，posting list存未压缩u32块号，排序字典二分查找。查询先按最短列表取候选并验证其余列表，再重建／小写路径精确校验；字节trigram可能跨UTF-8字符和路径分隔符，最终验证排除假阳性。
- 查询语义：空白AND子串，默认检索完整路径；`ext:`对最终文件名扩展名精确匹配；Unicode `to_lowercase`，无NFKC／完整casefold／拼音／fuzzy／regex。`first50`找到50条即停，少于50必须搜索完；`complete`计全部命中并只保留前50个ID，加校验和。**没有全量结果排序／TopK，也没有百万条命中列表分配**。
- 每规模3次独立进程建库，记录构建（含合成生成和posting构建）、写盘＋sync_all、文件尺寸与内存；构建p95仅3样本，相当于最大值，不能推断稳健尾延迟。Windows写盘＋sync_all不代表测试了真实断电耐久性。
- 热查：每case先对照线性完整扫描核验命中数、ID校验和与首50 ID，再按scan／block_trigram和first50／complete各31次；这一预热同时让索引和数据驻留。12种query固定顺序，算法没有随机轮换，不使用缓存查询结果。
- 进程冷：每case／mode启动15个全新进程，各加载整个索引，然后一次query。分别记录加载、query、同次加载＋query、PowerShell外侧墙钟。**OS page cache未清、索引之前刚生成并被反复读；磁盘／整机真冷p50／p95未测**。本轮没有清缓存、重启或修改系统设置。
- p50／p95用nearest-rank `sorted[ceil(n*p)-1]`，配对样本直接相加求加载＋query分位数，不相加两个单项分位数。n15的p95即最大值；无置信区间、随机化、独占CPU、优先级固定、频率／温度控制。采集中有短暂资料读取与约1秒新增夹具测试，未消除桌面及其他进程负载；热查与进程冷偶有相反尾延迟，不能把细小差异当作算法收益。

`GetProcessMemoryInfo`报告当前／峰值working set和private commit；PeakPagefileUsage字段是峰值commit，并非“硬盘交换文件大小”。[微软字段定义](https://learn.microsoft.com/en-us/windows/win32/api/psapi/ns-psapi-process_memory_counters_ex) 本原型**不使用mmap**，没有Linux RSS／PSS、watcher内核资源或Kite UI内存数据。不能把本次private commit与其他工具RSS直接混比。

## 取消与更新／恢复验证

取消测试：独立工作线程扫描无trigram的 `q`，主线程等到progress至少1024条后设置AtomicBool，计时从**发出取消到worker join**；每规模15次。每块至多64条验证后检查取消，此语料退出时检查了1024或1088条。

| 规模 | 取消p50／p95，ms | 退出结果 |
|---|---:|---|
| 100000 | 0.0348／0.0737 | 15/15 cancelled，未扫完整库 |
| 1000000 | 0.0341／0.1337 | 15/15 cancelled，未扫完整库 |

这个测试涵盖验证循环，**没有证明posting列表解压、交集、长查询解析、排序、I/O阻塞、扫描或压缩期间的取消上界**。原型在准备候选列表及短语列表搜索中未全面布置取消点；生产需要查询大小／时间预算及阶段检查点。UI迟到结果丢弃与真实快速输入也未测。

7个Rust测试通过（6个单元＋1个集成）：中文／短词／路径／扩展名／大小写的预期语义与scan对照；跨块／路径分隔符trigram与最终假阳性；2048条、12种case加200个编号查询的oracle；预取消／首50部分计数；二进制round-trip；新增／删除／重命名和丢事件后的对账模型；真实小夹具重扫。

更新模型用base＋overlay／tombstone，新增、删除、同ID重命名后与预期集合相符；模拟一次丢失新增事件，标dirty并重扫恢复；期间发生新事件时拒绝旧generation发布。它只在小型内存BTreeMap中测试，**没有接到百万条紧凑索引，没有增量写入性能、WAL或真正watcher**。

真实夹具创建在Loci工程 `work/fs-fixture-<pid>`，只有3个小文件及几个目录：验证新增中文名rs、改名成md、删除、target／.git排除；每次显式重扫，不依靠事件通知。完成后逐项清理，没有递归删除用户目录。

有限真实目录扫描只运行 `D:\Project\Kite`：**253个普通文件，0项读取错误**，遍历25.9580ms，建记录索引0.3532ms；匹配cargo9条、src/ui41条、ext:rs148条，与扫描oracle相符。报告以扫描当时仓库内容为准；之后新增文档会使复现计数变化。最多20000条文件，不跟随symlink／reparse point，排除target、.git、.agents、.codex、.scratch、artifacts、node_modules、resources、work；只列文件名／路径，不读取文件内容、不上传路径。该小样本没有样本量足够的真实文件系统p50／p95。
