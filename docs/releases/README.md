# 发布说明维护

每个正式版本在创建 tag 前维护一份同名文件，例如：

```text
docs/releases/v0.3.0.md
```

文件由维护者填写用户真正关心的内容，建议包含以下部分：

```markdown
# Kite v0.3.0

## 版本重点

用几句话说明这一版解决了什么问题，以及用户能直接感受到什么变化。

## 新功能

- 用户可见的新能力和使用方式

## 修复

- 触发条件、根因和修复后的行为

## 升级影响

- 配置、快捷键、安装目录、资源文件或兼容性是否有变化

## 已知限制

- 仍然存在的限制，以及临时规避方式
```

发布工作流会把这份说明与实际 CI 证据合并到 GitHub Release：tag 提交、提交范围、构建与安装验收记录、安装包大小和 SHA-256。正式发布必须提供对应说明文件；机器生成内容用于补充证据，不替代维护者说明。

完整流程见 [`../RELEASING.md`](../RELEASING.md)。本机只做必要检查；正式编译、打包、安装验收、校验和生成及上传由 GitHub Actions 完成。说明中分别记录代码检查、Actions 安装验收和人工 Windows 交互验证；同版本覆盖安装验收不能写成旧版本迁移已经验证。
