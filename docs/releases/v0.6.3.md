# Kite v0.6.3

## 版本重点

修复日常大量文件变动导致文件搜索停止同步、要求重建索引的问题。待处理身份与搜索变化层改为磁盘承载，移除 65,536 个存活变更对象、64 MiB 变化层和单次会话 512 MiB 日志的累计容量失败条件。

## 修复与恢复

- 待补读对象按文件身份在 SQLite 中合并，使用固定大小的读取页和刷新批次，大量新增、重命名、安装、解压及临时文件清理可以持续处理。
- 文件路径、目录映射、基库影子位和完整提交的全卷恢复游标在同一事务持久化；重启接续已提交位置，未提交的轮次重新读取。
- 分块传输保持整轮两阶段提交，先处理旧状态的目录变换，再统一提交本轮当前路径，避免后续目录事件破坏已经刷新的路径。
- 查询通过独立只读连接读取最后完整提交的视图，后台大轮次提交无需长期占用查询锁；目录处理与磁盘迭代可以响应取消。
- 同步日志按段轮转，消费确认后回收旧段；已删除记录复用数据库空闲页并整理 WAL。变化层自身可以直接查询，本版没有周期性全盘重扫或全基库重写。

## 升级影响

- 文件索引读取组件协议升级为 3。安装器更新已经安装的读取组件；旧组件与新主程序混用时提示更新，授权后重连。文件搜索继续默认关闭。
- 现有基库、索引格式和受保护的卷身份起点可以复用；升级前尚无持久恢复位置，且原始 USN 起点已经过期时，需要重建一次。卷或 journal 身份变化、实际日志连续性丢失仍要求重新建库。
- 排除目录、应用设置、Alias、固定项和启动历史继续保留。SQLite 变化数据仅保存在本机。
- 新增面向维护的 `--kite-file-index-session <data-directory>` 诊断入口，复用生产控制器，提供逐行 JSON 状态、查询、重建和停止操作。它只使用明确指定的数据目录，不自动安装读取组件或打开搜索结果。

## 验证与发布

- 本机完成必要编译、定向格式和差异检查；使用原有工具回放 3,255,185 条路径基库与 8,433 项真实变化，22 个关键词的完整查询、限量查询及原报告结果一致。
- 同一份真实变化转换为新逻辑轮次分块后，提交与查询结果同样一致，无 stale 或 rebuild_required。未新增 Rust 测试用例。
- 正式构建、官方插件、NSIS 打包、独立 Windows runner 的安装与文件同步验收统一由 GitHub Actions 执行；具体提交、安装包 SHA-256 和实际验收结果由下方自动报告提供。
- 安装验收覆盖全新安装、同版本覆盖、卸载、用户数据保留及读取组件的注册、实际替换和移除。专项同步验收覆盖超过 65,536 个存活变化对象、退出期间变化、同基库重启续读及日志切段回收。

## 验证边界

- 磁盘满、写入失败和实际 USN 连续性丢失会保留最后完整提交的数据并明确报错。
- 同版本覆盖验收不等于全部旧版本迁移验收；人工 UAC 拒绝、多屏、快捷键交互和长期在线观察单独记录。
- 安装包未做 Authenticode 数字签名。
