# Kite v0.5.0：搜索更顺手，结果更可控

Status: claimed
Category: enhancement
Target version: v0.5.0
Baseline: 当前仓库 v0.4.3
Scope: 版本功能规格；用户已授权按本规格实施并依 implement skill 在当前分支提交，不修改版本号或发布。

## Problem Statement

Kite 已经具备多路召回、自适应排序、用户 Alias、Pin、Demote、CLI 搜索、便携目录扫描和后台索引刷新。用户能够找到并启动应用，但遇到需要调整结果的场景时，操作还不够直接：

- 给已经选中的应用设置 Alias，仍要进入设置并再次查找目标；结果操作主要依赖右键菜单。
- Demote 只降低优先级，不能让不需要的应用入口完全退出建议列表；历史管理只有整体清空，无法单独纠正某个 Query 的学习记录。
- 某个应用没有被自动收录时，用户只能增加扫描目录、创建系统快捷方式或临时输入绝对路径，不能直接登记单个应用。

本版解决这些日常操作的额外步骤，同时保持明确匹配保护、低资源占用和经过验证的启动目标契约。

## Solution

交付三个按优先级排序的能力：

1. **P0 结果操作面板与直接设 Alias**：选中结果后，通过 Shift+F10 或右键打开同一组操作。复用已有打开所在目录、复制、Pin 和 Demote，在适用的应用结果上增加设置 Alias。用户无需离开搜索窗口或再次选择应用。
2. **P0 搜索偏好纠正**：用户可以隐藏某个应用入口，并在设置中恢复；对非空 Query 可以单独清除 Query History，保留其他 Query 的学习记录和全局 Usage。
3. **P1 手动添加单个应用**：用户在设置中粘贴应用的绝对路径，或从符合条件的路径直达结果选择“添加到 Kite”，确认显示名称后保存。首版支持 `.exe` 与现有解析器能够验证的 `.lnk`；登记后进入统一 AppItem 索引。

主窗口继续采用紧凑的原生界面。操作面板服务于当前结果，设置承担隐藏项和手动应用的持续管理。

## User Stories

1. 作为 Kite 用户，我希望用键盘打开选中结果的操作面板，以便无需切换到鼠标。
2. 作为 Kite 用户，我希望右键和键盘打开相同的操作，以便不用记两套行为。
3. 作为 Kite 用户，我希望操作面板只显示该结果可执行的动作，以便不用猜测不适用的操作。
4. 作为 Kite 用户，我希望打开面板后后台结果重排不会改变操作目标，以便不会对另一个应用执行动作。
5. 作为 Kite 用户，我希望直接给当前应用设置 Alias，以便不用在设置中再次搜索目标。
6. 作为 Kite 用户，我希望保存 Alias 后当前搜索立即更新，以便马上验证新简称。
7. 作为 Kite 用户，我希望 Alias 冲突时看见原目标和新目标并明确选择是否替换，以便不意外覆盖已有设置。

## Implementation Decisions

### 结果操作与直接 Alias

- 复用现有 UI 消息更新、结果上下文动作和 Alias 持久化模块。键盘和鼠标进入同一套适用动作判断与执行逻辑，不另建通用命令框架。
- 默认键盘入口为主搜索窗口处于搜索态时的 Shift+F10，非全局热键；设置页、独立工具窗和快捷键录制态不触发结果面板。键盘事件路由需支持该按键。面板内上下键选择、Enter 执行，Esc 关闭；Alias 编辑中 Esc 先取消编辑。关闭后恢复搜索输入或此前结果导航，Query 和选中目标尽可能保留。
- 面板保存打开时的结果身份和 Query，而不是可变列表下标。后台重排不改变动作对象；执行涉及应用修改或启动的动作前，按当前索引重新解析身份。目标已不存在或无法安全确认时显示原因，不执行到其他结果。
- 面板开启时阻止主搜索的 Enter、Alt+数字和结果导航处理同一个事件。IME 组合态禁止触发提交；普通文本编辑按键继续交给当前编辑框。保持现有全局热键、网页搜索快捷键和工具窗口交互。
- 可持久化的应用结果提供 Alias、隐藏、Pin 和 Demote 等适用动作；文件和路径结果复用已有文件动作；内置和插件结果仅保留各自已有的适用操作。首版不为文件、内置项或插件结果新增应用 Alias、应用隐藏或新的持久化类型。
- Alias 编辑直接绑定已确认的 AppItem 稳定身份，显示目标名称；非空 Query 可作为可编辑的 Alias 建议。沿用现有 Alias 规范化与匹配规则，不能只保存自由输入的目标名称。
- Alias 为空时不保存；已有同名 Alias 指向相同目标时幂等成功，指向不同目标时显示冲突并要求用户明确替换。取消不改变原映射。
- 持久化成功后刷新 Alias 和必要的基础候选缓存、推进相关搜索代际并重算当前结果；失败时保留输入并显示错误，不能给出成功提示。

### 隐藏与 Query 学习纠正

- **隐藏（Hidden）**是独立于 Demote 的用户选择：该应用启动身份不进入应用建议结果。产品动作名称为“隐藏此入口”。Demote 继续只影响排序，两者可分别恢复。隐藏不是卸载、索引删除或文件访问权限控制。
- 首版隐藏范围是索引中的应用和命令入口，覆盖正式与发现来源；不覆盖内置设置、系统入口、Everything 文件、路径直达、网页搜索和插件结果。
- 隐藏记录使用 AppItem 稳定身份并保留管理所需的名称、目标和参数摘要。在设置中集中列出并提供恢复；即使目标当前不在索引中，记录仍然可见且可以恢复。Alias 的目标选择候选不展示隐藏项，但原有 Alias 记录保留，并可显示其目标被隐藏。
- 隐藏过滤必须在最终归并与 Top N 截断前生效；空 Query 最近区和固定区同样过滤。隐藏结果不得消耗结果名额；已有 Alias、Name Exact、Pin 和历史加分均不能重新引入隐藏应用。未隐藏项继续遵守明确匹配保护和现有排序。
- 隐藏以选中 AppItem 的稳定启动身份为单位，不以整个安装族或所有启动归并组成员为单位。归并前移除该身份的全部候选；同组其他不同身份仍可成为代表项，不能继承隐藏身份的 Alias、Pin 或历史证据。它们对应其他入口，而不是隐藏失效；管理列表用目标与参数区分这些入口。同一身份的重复来源不允许绕过隐藏。
- 来源改变时，只有确认启动身份相同才通过既有身份迁移机制迁移隐藏记录；同名不同目标和同一程序不同启动参数不连带隐藏，不按显示名称匹配。
- 隐藏保留 Alias、Pin、Usage、Query History 和 Demote，恢复后这些数据继续适用。设置管理列表提供名称和目标用于区分同名项。
- “忘记此查询的学习记录”是 Query 级动作，对非空应用搜索 Query 提供，不属于某个选中应用。清除打开面板时捕获的 Query，而不是操作过程中后来输入的字符串；显示待清除的查询词。
- 沿用搜索与成功启动记录共同使用的 Query 规范化方式，只删除规范化 Query 对应的全部 Query→App 配对记录。空 Query 不执行清理；无记录时提示无需清理，重复清除不产生额外副作用。
- 清除不改变全局 Usage / Frequency / Recency、其他 Query History、Alias、Pin、Demote 或隐藏项。因此清除后某应用仍可能因名称匹配或全局使用习惯排在前面，UI 文案不能承诺恢复为无个性化排序。
- 隐藏、恢复和清除配对记录在存储成功后更新偏好快照并推进搜索代际，防止在途旧任务把旧偏好结果重新显示。基础候选缓存只在其依赖确实变化时失效；个性化从最新状态重放。
- 清除后允许从后续成功启动重新学习；暂停历史记录时仍可清除旧记录，恢复记录开关后再学习。既有“清空使用历史”范围继续是 Usage 与 Query History，不能顺带删除手动登记或隐藏选择。

### 手动应用登记与统一索引

- 应用登记、验证和索引合并归应用模块；持久化归既有 SQLite 存储模块；UI 只管理输入、状态和动作。沿用已有 rusqlite 与手写 SQL，不引入新数据库或新进程。
- 设置提供手动应用列表及“绝对路径 + 显示名称”的添加表单，支持修改名称与移除登记。首版以粘贴路径输入完成添加，不要求新增文件选择器依赖。
- 路径直达结果只有在路径指向可登记的 `.exe` 或 `.lnk` 时提供“添加到 Kite”；动作预填路径并进入同一验证与确认流程。普通文件、目录、URL、设备路径和不存在路径不提供此动作。
- 使用既有绝对路径校验及快捷方式解析能力。新登记必须在保存时验证目标，无法解析或不能形成现有启动链可接受目标的快捷方式不保存。图标提取失败使用既有默认图标，不影响有效应用登记。
- `.lnk` 沿用其经过解析的静态参数、工作目录和图标来源；直接 `.exe` 未指定工作目录时沿用现有启动默认值。首版不提供用户编辑参数、工作目录或终端的表单，也不把 Query 转换成启动参数。
- 登记保存原始入口路径、用户显示名称和登记身份；扫描及重建时重新验证并生成可启动 AppItem。搜索与偏好使用当前由规范化 target 与 args 形成的稳定身份，而不是显示名称、来源或登记记录 ID；本版不扩展稳定 ID 的工作目录维度。工作目录是保留的启动元数据，沿用现有验证与启动规则。
- 手动应用作为用户明确添加的正式入口参与 SourceLayer / Tier 规则，进入同代 AppItem 快照和 RetrievalIndex，支持普通名称、中文、拼音、Alias 和个性化搜索。
- 手动入口与自动入口作为原始应用候选一起进入现有扫描去重和发现项归并，不能在最终 AppItem 列表上直接追加。相同稳定启动身份合并为一个展示结果，已验证的手动登记作为首选入口，保留其用户显示名称和导入的启动元数据；自动入口名称仍保留为可搜索名称证据。不同目标或不同语义参数保留。重复登记相同启动身份时复用现有登记并提示已添加，不产生重复行。
- 显示名称修改不改变启动身份。手动与自动来源的首选入口切换，只在同一启动身份内迁移已有 Alias、Pin、Usage、Query History、Demote 和隐藏状态；不因名称相同或原始快捷方式路径相同就迁移到新的启动目标。
- 外部修改 `.lnk` 后，在既有后台重扫或手动重扫中重新解析。若启动语义改变，作为新的启动身份处理，不把旧偏好自动赋给新目标。原有全局 CLI 终端选择和命令来源默认从用户主目录启动的契约保持。
- 已登记目标消失时，登记留在管理列表并标记不可用，不生成可启动建议，也不自动删除登记。目标恢复后在既有索引重建中恢复可用；不增加高频扫描或新的全盘索引。
- 移除登记仅删除 Kite 的登记记录和该记录提供的自定义名称，随后重建索引；不删除任何软件文件。若仍有相同启动身份的自动入口，继续保留该入口和其原有偏好。若不再有任何入口，旧偏好不自动转移到其他目标。
- 持久化手动登记不依赖扫描缓存或临时路径结果；快速与完整索引构建均包含有效手动入口，避免重启首屏暂时遗漏。保存、改名或移除后走现有单飞重建与原子快照切换。

### 数据与兼容

- 隐藏记录和手动登记新增到现有本地存储；Query History 使用现有表结构。表结构迁移遵循当前存储版本规则，并保持旧库设置、Alias、Pin、Usage、Query History 与 Demote。
- 写入及迁移失败时显示错误并保留此前有效状态；多步持久化变更使用事务。成功提示必须对应已完成的存储操作，不将临时 UI 状态当作已保存。
- 现有稳定身份不随来源变化；兼容旧来源 ID 时，复用统一身份迁移入口并以事务迁移全部相关状态。当前迁移尚未覆盖 Demote，实施中将它与新增隐藏记录一并纳入，不为手动应用另建身份迁移流程。
- 本版遵守“历史存储用 rusqlite + 手写 SQL”和“文件搜索走 Everything”的既有 ADR；不改变文件模式下文件优先、网页槽位或 Everything 依赖提示。

## Testing Decisions

用户已确认：复用现有搜索评估、SQLite 存储测试和 UI 消息交互测试，再以 Windows 安装版验收真实操作。

- 以外部可观察行为为断言：最终列表中的稳定目标身份、顺序与数量，存储重载后的用户选择，消息处理后可用动作、绑定目标、输入和焦点状态。避免固定内部调用次数、评分常量或表布局。
- 搜索的主要 seam 是既有统一搜索入口：同代索引 + Query + Alias / 个性化 / 隐藏选择 → 最终 Top N。沿用已有固定 fixture 和搜索评估；冷缓存、热缓存及在途搜索必须呈现相同隐藏和纠正语义。
- UI 的主要 seam 是既有消息更新入口，沿用共享测试状态和上下文菜单重排回归；覆盖键盘、右键、Alias 编辑、保存失败、IME、Esc 层次和过期目标，不构建一套新的 UI 模拟框架。
- 持久化的主要 seam 是既有 HistoryDb 行为接口及旧库迁移测试，覆盖隐藏/恢复、按 Query 清除、手动登记、关闭重开和事务失败。按 Query 清除以保留其他数据为核心断言。
- 手动应用使用隔离临时目录、实际 `.exe` 路径和可解析快捷方式 fixture 走登记到索引再到搜索的路径。沿用现有扫描归并与启动身份测试，验证来源切换时偏好保留及不同启动语义不误合并；Windows 上再验证真实启动。

| 场景 | 必须观察到的结果 |
| --- | --- |
| 搜到应用 → Shift+F10 → 设 Alias → 搜该 Alias | 直接绑定原目标；立即生效；重启后保留；冲突替换可取消 |
| 操作面板打开后结果重排或索引刷新 | 动作仍绑定原目标；目标失效时明确拒绝；不操作新的列表占位项 |
| 隐藏精确名称、Alias、Pin 或高频命中的应用入口 | 普通与空 Query 列表均无该启动身份；有足够未隐藏候选时补足名额；其他明确匹配保护不变 |
| 隐藏项同时具有重复来源，或属于多身份归并组 | 同身份重复项全部隐藏；其他启动身份仍可独立显示，不继承被隐藏身份的偏好证据 |
| 热缓存命中与在途旧搜索之后隐藏或恢复 | 列表遵守最新选择，旧任务不能重新显示隐藏项；恢复后重新可检索 |
| 清除一个 Query 的配对学习 → 存储重载 | 该 Query 全部配对记录消失，其他 Query、Usage、Alias、Pin、Demote 和隐藏选择保持 |
| 用大小写及首尾空格变体清除 Query | 依据现有规范化处理同一记忆；空 Query 不触发批量清除 |
| 添加应用 → 重扫 → 重启 → 搜索 → 启动 | 首屏和完整索引均包含有效入口；实际启动目标正确；固定与 Alias 可用 |
| 同一身份已有扫描入口再手动登记、改名及移除 | 展示一次；用户名称和原名称均可搜索；移除后自动入口仍存在且偏好保持 |
| 同名不同目标、同 exe 不同语义参数、快捷方式改目标 | 不误归并，不把旧 Alias、Pin、历史或隐藏状态赋给新启动身份 |
| 无效新增目标、已有目标消失、存储写入失败 | 不生成错误可启动结果或虚假成功提示；原有登记与设置可继续管理 |
