# 04：只清除当前 Query 的配对学习

Status: done
Category: enhancement
Blocked by: 01 结果操作面板与键盘入口

## What to build

用户在非空应用搜索中选择“忘记此查询的学习记录”，只清除该规范化 Query 对所有应用的配对记忆，立即重算结果，并能从后续成功启动重新学习。

## Ownership and contracts

- 负责 Query 级面板动作、既有 Query History 的精确清除、偏好刷新及存储/搜索/UI 回归。
- 清除打开面板时捕获并显示的 Query，而不是后续输入或某个选中应用；沿用搜索与记录启动共同使用的规范化方式。
- 保留全局 Usage/Frequency/Recency、其他 Query History、Alias、Pin、Demote 和已存在的隐藏选择。
- 不改变基础召回，不无故清除基础候选缓存；更新偏好快照并使旧结果代际失效。
- 与 03 没有技术阻塞关系；03 完成后再增加保留隐藏选择的组合验收，不因此把本任务延期到 03 之后才能开始。

## Acceptance criteria

- [x] 清除后该 Query 的全部配对记录消失，其他 Query 与全局使用记录保持。
- [x] 大小写、首尾空格变体按现有规范化处理同一记忆；空 Query 不清理任何记录。
- [x] 无记录及重复清除安全，并显示无需清理的准确反馈。
- [x] 暂停历史记录时仍能清除；恢复记录后可从成功启动重新学习。
- [x] 当前结果立即依据剩余偏好重算，旧 worker 响应不能恢复已清除的配对效果。
- [x] 文案仅承诺清除配对学习，不承诺无个性化排序或某应用一定退位。
- [x] 关闭重开存储后数据一致；清除失败明确提示，不显示成功。

## Validation

- 为同一应用记录两个 Query，并设置 Usage、Alias、Pin 和 Demote；只清除一个 Query 后检查所有保留数据。
- 复用搜索与 UI 消息测试验证缓存命中、旧任务及重新学习；03 合入后补组合断言，07 再做整体操作验收。
- 运行受影响的存储/搜索/UI 回归及 `cargo check`。
- Windows 开发构建演示清除一个查询、搜索另一个查询及后续重新学习。
