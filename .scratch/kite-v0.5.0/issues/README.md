## 认领与执行

- 01–06 的实现按职责分配到 application、storage、search 和同一 UI 所有者；共享 UI 按依赖顺序接入，主 Agent 负责组合验收。
- 推荐实施顺序是 01 → 02 → 03 → 04 → 05 → 06 → 07，以先交付 P0 再交付 P1。此顺序是交付安排，不将没有技术依赖的任务强行写成阻塞边。
- 02、03、04 都依赖 01，但会修改共享 UI 状态、动作和偏好刷新区域；采用分别认领、顺序集成。只有明确隔离了修改所有权后才并行。
- 每张任务自行完成其必要回归和 Windows 冒烟，07 负责组合操作、安装版、升级和性能基线验收。
- 认领后更新相应任务状态；完成时在该任务的 Comments 中记录实施、验证证据及未验证项。执行者遵循当前项目规范，不覆盖其他人的改动。
- 本轮授权包含产品实现和当前分支本地提交；版本号修改、推送、正式发布仍需后续明确指令。
