## Problem Statement

Kite 已能从开始菜单、桌面、Scoop、App Paths 和 UWP 建立 AppItem 索引，并结合 MatchScore、Usage、Recency、Query History 与 Pin 排序。但索引主要在启动或手动重扫时重建：运行中安装、卸载或修改入口后，Query 可能继续显示旧结果。开始菜单深层入口曾因扫描深度不足而漏掉；本地未提交修复扩展了快速扫描深度，并让去重区分同一 exe 的不同参数，但尚无后台完整扫描和自动更新。名称有英文词间空格时，连续输入也可能无法召回。不同来源指向同一程序时，原始 exe 名、友好快捷方式和历史记录可能分散或竞争；图标在来源变化后可能仍显示旧缓存或占位符。用户需要的是及时、安静、稳定的搜索结果，而不是理解各入口来自哪里。

本轮以 Win32 应用入口的自动更新、通用降噪、个性化排序和图标可用性为一个搜索体验闭环。当前已修复的英文词尾误召回、原始 App Paths 入口降序、回收站图标生成及部分损坏缓存，作为回归基线保留；控制面板仍显示不对应的通用系统图标。

## Solution

Kite 先用有预算的快速扫描提供首屏结果，再在后台完整遍历受支持的开始菜单和桌面入口，补齐遗漏并原子切换索引；运行中入口变化也能触发后台刷新。相同启动语义的入口只展示一个首选结果，不同参数的入口保留。图标源、图标序号和缓存失效规则恢复正确后，再基于固定样本改善分词、连写、单词前缀和自动缩写召回。基础相关性决定候选层级，History 只在相近质量的候选间学习偏好；用户 Alias、Pin 和明确匹配保护继续生效。

验收以真实 Windows 上的安装、卸载、快捷方式变更、重复入口、历史排序和图标显示为准；Rust 回归测试锁定可复现的输入与结果。使用固定 Query 样本记录相关性和端到端延迟基线，再决定分数或缓存策略，不以单个产品名称写特例。

## Delivery Sequence

1. **P0 索引完整性与身份**：保留快速扫描的启动时间预算；后台完整递归扫描已支持的 Start Menu/Desktop 入口，不跟随 junction，异常入口单独跳过。后台结果补齐快扫遗漏并刷新当前 Query。去重先按规范化 `target + args` 判断启动身份，仅当工作目录确实改变启动语义时才纳入；同名不同目标、同 exe 不同参数均保留。规格制定时已有的“快速扫描加深目录、target + args 去重”改动纳入回归验收，不将其误当作后台完整扫描。
2. **P1 图标链路**：`.lnk` 的 `GetIconLocation()` 返回路径和序号，二者都传入现有图标提取链；验证负序号资源、无扩展名 ICO、无效优先源到 target 的回退及旧快捷方式/PNG 缓存失效。CC Switch 和控制面板作为实机回归样本；图标存在不等于图标内容正确。
3. **P1 搜索评估基线**：建立固定的 `tests/search_cases.json`，保存 Query、稳定目标身份及 Top 1/Top 5 期望，在改评分前记录 Top1 Accuracy、Recall@5、MRR、重复入口数和延迟。索引覆盖率另行统计，不能把未入索引的应用误判为 matcher 失败。
4. **P2 召回特征**：在现有 normalizer/matcher/ranker 分工内依次加入 Token Match、Compact Name、Word Prefix 和通用 Acronym；分别用多词、连写、`ter` 与 `vsc` 等样本锁定行为，不按应用名新增算法分支。
5. **P3 排序与学习**：先按基础相关性分层，再在同层或相近质量候选间应用 Query History、使用次数和近期使用；重调分数以固定测试集的 Top 1 与 MRR 改善为准，保留用户 Alias、Pin 和明确匹配保护。

## Implementation Decisions

- 保持扫描、搜索召回与排序、历史存储、图标缓存、Iced 界面各自的职责；界面只消费索引快照并触发搜索刷新，不承担入口去重或打分逻辑。
- 监听用户和公共开始菜单、桌面、已配置 Scoop shim 目录，以及当前支持的 App Paths 注册表视图。变化通知合并为后台刷新；监听失败或漏报时保留手动重扫。不得每隔固定时间扫描整个系统。
- 同一时刻最多进行一次索引构建；突发事件合并，构建期间到来的变化在完成后继续处理。发布完整新快照，旧构建结果不得覆盖较新的状态；当前 Query 随快照更新。
- 继续复用现有快捷方式解析缓存。缓存命中取决于入口内容的可验证变化，不能把“缓存有效”当作“索引不需要刷新”。快速扫描受 1.5 秒预算约束并尽早发布可用快照；后台完整扫描不复用这个时间预算，不因快速扫描提前停止而永久漏掉后续目录。
- Win32 入口同一性的默认键为规范化 target 与原始启动参数；仅对已证明工作目录本身区别功能的入口增加工作目录维度。来源名称仅决定展示优先级。不能仅凭同名或共同父目录合并，也不能把用户 Query 当作待执行命令。快捷方式启动参数须保持 Windows 原有引号语义。
- 首选开始菜单或桌面的可读入口；App Paths 与原始 exe 可搜索但适度靠后。对于不能确认相同启动语义的近似入口，先保留可启动结果，避免错误去重。
- AppItem 身份在来源变化时尽量稳定。若现有持久化 id 必须变化，应迁移或兼容 Usage、Query History、Pin 和 Alias，且不得把历史转给不同的可执行 target。
- 保留 MatchScore 为主信号、Query History 为重要个性化信号，以及明确匹配保护。基础匹配质量先划分候选竞争层级，历史只在相近质量候选间调整顺序；不能用历史为完全无关的候选补分。Pin 与历史加分不叠加越过保护界限；同一程序的入口展示优先级可单独处理，不能无条件降低所有精确匹配。
- 搜索特征在现有职责模块内演进：Normalize/Tokenize 产生原名、紧凑名称与单词边界；Matcher 区分 full exact、compact exact、word exact/prefix、ordered token、acronym、pinyin、alias、substring、fuzzy；Ranker 合并基础质量与受限历史偏好。`Visual Studio Code` 的 `visual code`/`vs code`、`Microsoft To Do` 的 `todo`、`XTerminal` 的 `ter` 和多词首字母 `ndm`/`vsc` 是通用规则的样本。原始名称、原始 Query、Alias 和启动 target 保持不变。自动缩写与紧凑匹配低于真实名称精确匹配及用户 Alias，并限制短片段误召回，不写产品专属分支。
- 中文品牌名与英文商标之间无法可靠地算法推导；常见、明确的跨语言同义称呼可作为受控内置 Alias 数据维护，匹配已索引的目标名称片段，不能绕过入口索引创建虚假的可启动 target。用户 Alias 优先于内置 Alias；歧义词不自动点名某一个应用。
- 系统工具、普通应用、网页搜索与 Everything 文件结果维持各自的召回边界；本轮只改善系统工具噪声对应用搜索的影响，不改变文件搜索的可选开关和 Everything 依赖方式。
- `.lnk` 解析得到的 icon path 与 icon index 必须作为一个图标来源保留下传；沿用现有 `path,index` 解析及 Windows 资源提取链，包含负序号资源。快捷方式图标源也允许通过文件内容识别无扩展名的 ICO；优先源无法给出应用图标时，再尝试已验证的启动 target。不能把来源文件的通用白纸关联图标当作提取成功，也不能因此绕过 target 回退。
- Shell 虚拟入口优先从当前系统命名空间对象取得对应图标；仅在语义确实对应时使用 stock icon 回退。通用软件图标不能冒充控制面板等具体系统入口。
- 图标以可验证的源变化失效，损坏或全透明的缓存重新提取；`icon index` 被旧版快捷方式解析缓存丢掉时须升级或迁移 scanner cache，让旧条目重新解析。提取策略修正后还须让旧版缓存中内容有效但语义错误的通用图标重新生成，无需用户手工清缓存。系统虚拟入口和文件类型图标保留统一回退。更新后的图标必须在实际列表中可见，不能只修改磁盘 PNG 而被界面缓存继续显示旧图。
- 对图标缓存增长和文件关联图标的失效方式分别记录与验证，不把 AppItem 索引刷新、快捷方式解析缓存和 PNG 图标缓存混成一个固定 TTL。
- 开始菜单快速扫描覆盖常见多层程序文件夹并保留时间、目录和总量上限；后台完整扫描递归遍历受支持的开始菜单/桌面入口，不受快速扫描的深度和时间预算限制。后台仍不跟随 junction，单个入口失败继续扫描；如安全上限触发则记录未覆盖目录和原因，不能静默宣称已完整索引。构建在后台运行并发布完整快照，不阻塞热键或输入。
- 对索引来源建立本地覆盖检查：把 Windows 可见且可启动的开始菜单入口与扫描结果对照，记录被深度、预算、解析、有效性过滤或去重挡下的类别。缺口按原因修复，不靠品牌清单或向 PATH 批量添加可执行文件。
- 不引入云服务、用户行为上传或新的搜索索引数据库。历史继续使用现有本地 SQLite 决策，文件搜索继续遵守 Everything 的既有 ADR。

## Testing Decisions

- 主要测试缝为“受控入口变化 → AppItem 索引快照 → 同一 Query 的最终结果”。测试观察可见名称、顺序、target、图标和可启动性，不断言内部函数调用次数或具体分数常量。
- 对扫描器使用临时目录和可控注册表测试替身或隔离环境，覆盖创建、删除、改名、多层开始菜单、参数不同、来源重复、坏快捷方式、快速预算提前结束后由后台补齐和突发事件；将 NVIDIA App、Razer Synapse、Git Bash/CMD/GUI 及多个 PowerShell 入口纳入端到端样本。Windows PowerShell、PowerShell 7、ISE、Developer PowerShell 的身份和参数需分别核对，实际点击后窗口应保持运行。一条坏入口不能清空整份索引。
- 对搜索管线使用固定的中英文 Query 样本、别名、拼音、系统工具、原始 exe 与友好入口，验证首位或前三位、重复数量、无关结果和明确匹配保护。`tests/search_cases.json` 的每个样本记录 `query`、固定索引 fixture、`expected_top`、`expected_in_top5`、`forbidden_top`（禁止占据首位）及适用的历史状态；期望指向稳定 fixture 身份，不仅是可能重名的显示名称。加入 `To Do`/`todo`、`visual code`/`vs code`、`vsc`、`wt`、`ndm`/Neat Download Manager、`雷蛇`/Razer、`ter`/XTerminal、用户 Alias 与自动首字母冲突、真实精确匹配与紧凑匹配竞争、短 Query 误召回的回归样本。产品名只作为样本数据，不在扫描或排序规则中写特例。
- 对历史使用隔离的本地库，验证同一 Query 多次选择 XTerminal 等候选后在同质量层内的排序变化，以及清空或暂停记录后排序的外部行为；验证 History 不能把低相关 substring/fuzzy 推到高相关 word-prefix 或 exact 之前，身份迁移不误绑 Pin 和 Alias。
- 对图标使用真实 Windows 图标提取、损坏缓存、源更新与显示刷新测试；加入“.lnk 图标路径带非零或负资源序号”“无扩展名但头部为 ICO 的 MSI 图标源”“优先源只返回通用白纸图标而 target 带应用图标”“升级前缓存了错误但有效的 PNG”四类回归。CC Switch 同时检查快捷方式解析值、缓存迁移、最终列表图标，不能仅因修复了 icon index 就判定它已通过。对控制面板、回收站等 Shell 虚拟入口，在同一 Windows 上核对列表图标是否对应系统对象，而不只检查 PNG 是否存在。在真实列表中检查系统入口、普通 exe、快捷方式、Scoop、UWP 和常见文件类型的图标覆盖率。
- Windows 端到端验收覆盖开始菜单、桌面、Scoop、App Paths 的安装/卸载/改名。以最后一次入口变化后 5 秒内看到稳定结果为目标，记录超时和原因；更新过程中搜索可用，且一次安装事件不会产生持续重扫。
- 对同机 Windows 开始菜单中的可启动应用做覆盖抽样，确认深层目录和带参数快捷方式进入索引，同时核对未进入索引的过滤原因；不能只在写死的三个应用上通过。
- 用同一套匿名化 Query 与索引样本记录 Top1 Accuracy、Recall@5、MRR、重复入口数、图标覆盖率和“输入 → 列表更新”的 P50/P95/P99；先跑改动前 Kite 基线，再逐项加入特征并比较，不因单个截图调一次分数。索引覆盖率单独以 Windows 可启动入口为分母统计，并标出扫描、解析、过滤和去重各自造成的缺口；若与 Flow Launcher 比较，应在同机、同查询和相近索引覆盖下实测，不能用唤起速度代替搜索相关性。
- 沿用当前 Rust 回归测试与 Release 构建检查；Windows 行为须在真实机器上做可见结果和进程稳定性验证，编译通过不算完成。

## Out of Scope

- 自建 NTFS 全盘文件索引、替换 Everything、改变文件搜索默认开关。
- UWP/Store 安装事件的实时监听；本轮仍通过启动扫描与手动重扫覆盖 UWP，另行评估可靠的系统事件源。
- 为任何特定品牌、产品名、exe 名或目录写专属扫描、去重或打分分支；受控的跨语言别名数据不属于专属算法分支。
- 插件系统、云同步、遥测、AI/向量/Embedding/LLM 搜索、Tantivy、SQLite FTS、Elasticsearch、跨平台实现，以及界面视觉重做。本轮应用索引规模不需要这些新技术栈。
- 固定间隔全盘重扫、仅凭一个时间 TTL 判断所有缓存过期。
- 把 PATH 中所有命令行 exe 直接当作应用入口；本轮先恢复已存在的可启动开始菜单快捷方式，避免引入大量工具命令噪声。
- 签名、版本号、推送、合并和发布。

## Further Notes

- 当前索引在启动及托盘手动重扫时构建；快捷方式解析缓存按路径、修改时间和大小复用，图标缓存另有来源时间检查。三者生命周期不同，需要分别验收。
- Flow Launcher 和 PowerToys Run 的程序源实现提供了入口变化监听、突发事件合并与来源去重的参考；这里只借鉴可验证的行为，不照搬其技术栈或所有缓存时长。
- 本机 CC Switch 的桌面快捷方式指向现存的应用 exe，图标位置是 MSI 安装目录下无扩展名的 `ProductIcon`；文件头为有效 ICO（`00 00 01 00`）。当前缓存生成的是通用白纸 PNG。`.lnk` 解析还独立丢弃了 `GetIconLocation()` 的图标序号；两条缺口应分别验证，不能假定补序号即可修好 CC Switch。该应用的开始菜单快捷方式比已提交基线的扫描深度多一层，因此这里只把它作为一般性回归样本，不添加产品名特例。
- 本机 NVIDIA App、Razer Synapse、Git Bash/CMD/GUI 的开始菜单快捷方式均位于规格制定时已提交基线的两层限制之外；当时本地扫描修复已提高快速扫描深度，并以 target + args 保留参数不同的 PowerShell 等入口，但后台完整扫描、入口变化监听和实机界面验收仍待后续任务完成。系统 PATH 另有 `git.exe`，本轮通过开始菜单入口恢复用户可见的 Git 应用结果，不扩大为任意命令行程序索引。
- 本机控制面板缓存不是空文件，而是当前代码所选的通用软件 stock icon；截图中的小图标与缓存一致。此例验证“图标内容正确”，不应误写为“图标提取失败”。
- Microsoft To Do 已在 AppItem 索引中；`To do` 能搜到而 `todo` 只能返回网页搜索。当前规范化只压缩连续空白，名称匹配不比较去掉英文词间空白后的形式，模糊匹配又只检查全名或单个词，因此属于召回缺口，而非安装入口漏扫。
- Neat Download Manager 已可通过 `download` 召回，`ndm` 是多词英文名称的首字母缩写；当前拼音首字母字段对英文逐字符保留，无法自然产生 `ndm`。`雷蛇` → Razer 则是跨语言品牌同义称呼，须与自动首字母区别处理，而且只有 Razer 入口进入 AppItem 索引后别名才能返回它。
- 先建立可复现的 Query/索引评估样本和当前基线，再调整去重与个性化权重；自动刷新可以独立验收，但最终仍以完整搜索列表的表现为准。
- 本规格已由 `/to-tickets` 按“索引完整性与身份 → 图标链路与评估基线 → 召回特征 → 排序/History → 实机验收”拆为关联任务；完成状态以这些任务及验证记录为准。目标仍是先保证 Windows 常见可启动应用能入索引，再让自然缩写、分词、连写和模糊输入可靠召回，最后用历史行为把相关结果推到首位。
